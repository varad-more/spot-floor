This is a price comparator, not an availability one. AWS does not publish spot availability, so every availability cell below reads unknown — deliberately, as a word rather than a blank. The nearest thing AWS offers, Spot Placement Score, is computed against the calling account's quota and history, so a score fetched with this app's credentials describes this account and not your odds of getting capacity. spotfloor does not call that API under app credentials and reports unknown rather than inventing a number.

“Price moves” is not availability either. It counts how many times the price changed in the window — a real fact from AWS's published history, and a fair hint that a zone is contended. It is not a fulfillment probability and is not presented as one.

  • A region row names its zone. AWS prices spot per availability zone, and zones inside one region differ. The price shown is the cheapest zone in that region, and the AZ spread column states how much the roll-up hid — a big spread means the regional number alone is not actionable.
  • Instance types are compared across regions, and that is honest. m5.large is the same 2 vCPU / 8 GiB machine in every region, so the prices are directly comparable. No SKU normalization is needed or done.
  • Gaps in a sparkline are gaps. A bucket with no observation is drawn as a break, not interpolated — not observed is a different claim from unavailable.
  • Spot prices only (Linux/UNIX), per instance, per hour. On-demand rates are a different API and are not shown. The watchlist is {{ config.instance_types | length }} instance types — bounded on purpose, because us-east-1 alone lists 1,354.
