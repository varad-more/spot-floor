Why “spot floor”?

AWS will not sell you a spot instance for less than a tenth of its on-demand price. Bid theory says a spot price should fall until demand meets supply. It doesn't. It falls to {{ floor_ratio_pct }}% of list and stops dead — no matter how idle the capacity, how unfashionable the instance, or how empty the region. That wall is the spot floor, and it is what this tool is named after.

It is not a rule AWS publishes. It is one you can see, which is why the numbers beside this paragraph are measured on the {{ '{:,}'.format(floor.priced) }} rows currently in the table rather than quoted:

  • {{ '%.4f' % floor.min_ratio }}× is the cheapest spot price anyone here gets, as a fraction of on-demand — against a theoretical floor of {{ '%.2f' % floor_ratio }}×. {% if floor.below_floor %}Only {{ floor.below_floor }} row{{ '' if floor.below_floor == 1 else 's' }} sit{{ 's' if floor.below_floor == 1 else '' }} below it, by less than a hundredth of a cent — quantization, not a discount. {% else %}Not one row of {{ '{:,}'.format(floor.priced) }} goes below it.{% endif %}
  • {{ '{:,}'.format(floor.at_floor) }} rows ({{ '%.1f' % floor.at_floor_pct }}%) are pinned exactly to it — priced at the floor because there is nowhere further down to go.
  • {{ '%.4f' % floor.max_ratio }}× is the most anyone pays. Spot is capped at the on-demand price too, so the whole market lives inside a band one order of magnitude wide.

What that means when you are picking. A row at the floor is at its structural minimum: waiting will not make it cheaper, and the only way to pay less is to launch the same hardware somewhere else. A row well above the floor has room to fall — and room to rise. Sort by Saves to see which is which.

Why availability is unknown, and what “price moves” measures

AWS does not publish spot availability. The nearest thing, Spot Placement Score, is computed against the calling account's quota and history — so a score fetched with this app's credentials describes that account, not your odds of getting capacity. spotfloor does not call that API and reports unknown rather than inventing a number. This is a price comparator; it does not claim to know what you can get.

“Price moves” is not availability either. It counts how many times the price changed in the window — a real fact from AWS's published history, and a fair hint that a zone is contended. That hint is where it ends.

  2. Point boto3 at the key — however you normally would: 
    aws configure                       # writes ~/.aws/credentials

    Run aws configure yourself. Never paste keys into files in this repository.

    uv run python scripts/check_setup.py
    It tests each piece separately — credentials resolve, credentials are valid, each IAM action, a real live price — and names the exact fix for whatever fails. It never prints secret material.
